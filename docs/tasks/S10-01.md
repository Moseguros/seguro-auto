## Contexto

Primeira tarefa do Sprint 10 (Reclamações, provedor e assistência). RF-10 e RF-27, e os deveres do DL 1/2026 sobre reclamações. Um tomador, segurado, beneficiário ou terceiro lesado reclama a partir de uma apólice, de um sinistro, de um pagamento, de um mediador ou de um serviço; a seguradora confirma a recepção, analisa, conversa com o cliente (com notas internas que o cliente nunca vê) e responde com fundamentação, dentro de prazos lidos de `complaint.sla_config`. ADR-002 (RLS), ADR-005 e ADR-006 (`FileAccessPolicy`). O provedor (S10-02) e os processos externos (S10-03) usam as colunas que esta tarefa já cria.

## Objectivo

O cliente cria uma reclamação na API, conversa com a seguradora e aceita a resposta. A seguradora confirma a recepção, atribui, pede informação, escreve mensagens e notas internas e responde com um PDF formal. Os prazos vêm sempre de `complaint.sla_config`. As notas internas nunca chegam ao cliente nem ao provedor: nem pela API nem por SQL directo no âmbito deles.

**Guarda de colunas por âmbito** — o provedor e o cliente podem mudar o estado, mas não os dados da reclamação. Gatilho na mesma migração:

```sql
create function complaint.guard_complaint_update() returns trigger language plpgsql as $$
declare
  s text := current_setting('app.scope', true);
  i uuid := nullif(current_setting('app.insurer_id', true), '')::uuid;
  allowed text[];
begin
  if s = 'SYSTEM' or (s = 'ORG' and old.insurer_id = i) then
    return new;                                    -- seguradora e sistema: sem restrição de colunas
  elsif s = 'ORG' then                             -- provedor (S10-02)
    allowed := array['status','sla_due_at','closed_at','closure_reason','updated_at','updated_by','version'];
  elsif s = 'CUSTOMER' then
    allowed := array['status','sla_due_at','escalated_at','ombudsman_org_id','has_external_proceeding',
                     'last_customer_message_at','closed_at','closure_reason','updated_at','updated_by','version'];
  else
    raise exception 'complaint: update not allowed' using errcode = '42501';
  end if;
  if (to_jsonb(new) - allowed) is distinct from (to_jsonb(old) - allowed) then
    raise exception 'complaint: columns not writable in scope %', s using errcode = '42501';
  end if;
  return new;
end $$;
create trigger trg_complaint_guard before update on complaint.complaint
  for each row execute function complaint.guard_complaint_update();
```

### 4. Prazos (`SlaCalculator`, regras numeradas)

Decisão provisória (ver "Questões"): horas corridas para a confirmação e **dias de calendário** para a resposta e para o provedor; sem suspensão do prazo durante `INFO_REQUESTED`. Fuso `Africa/Maputo` (UTC+2, sem hora de Verão).

1. Configuração efectiva: a linha de `sla_config` com `insurer_id` da reclamação; se não existir, a linha `insurer_id is null`. Nunca há valores no código; `SlaCalculator` recebe a configuração por parâmetro.
2. `ack_due_at = submitted_at + ack_hours horas` (instante exacto).
3. `answer_due_at = (data local de submitted_at + answer_days dias) às 23:59:59 locais`, convertido para UTC. Em Java: `submitted.atZone(MAPUTO).toLocalDate().plusDays(answerDays).atTime(23, 59, 59).atZone(MAPUTO).toInstant()`.
4. O prazo do provedor (S10-02) usa a mesma regra a partir de `escalated_at` com `ombudsman_days`.
5. `sla_ack_hours` e `sla_answer_days` são copiados na criação; mudar a configuração só vale para reclamações novas.
6. `sla_due_at` (prazo da fase actual): `SUBMITTED` → `ack_due_at`; `ACKNOWLEDGED`, `IN_ANALYSIS`, `INFO_REQUESTED` → `answer_due_at`; `ESCALATED_TO_OMBUDSMAN`, `OMBUDSMAN_ANALYSIS` → prazo do provedor (S10-02); outros → `null`. `slaStage` na API: `ACK`, `ANSWER`, `OMBUDSMAN` ou `null`.
7. `overdue = sla_due_at is not null and agora > sla_due_at`.

| `subjectType` | sim | `POLICY`, `CLAIM`, `PAYMENT`, `BROKER`, `SERVICE`, `OTHER` |
| `policyId` | `POLICY`, `BROKER`; opcional em `SERVICE`/`OTHER`; proibido nos outros (`NOT_ALLOWED`) | uuid |
| `claimId` | `CLAIM`; proibido nos outros (`NOT_ALLOWED`) | uuid |
| `paymentIntentId` | `PAYMENT`; proibido nos outros (`NOT_ALLOWED`) | uuid |
| `insurerId` | `SERVICE`/`OTHER` sem `policyId`; proibido nos outros (`NOT_ALLOWED`) | uuid |
| `complainantRole` | `SERVICE`/`OTHER` sem `policyId`; proibido nos outros (`NOT_ALLOWED`) | `POLICYHOLDER`, `INSURED`, `BENEFICIARY`, `THIRD_PARTY` |
| `category` | sim | valores da tabela |
| `description` | sim | sem espaços nas pontas; 20–4000 (`TOO_SHORT`, `TOO_LONG`) |
| `desiredOutcome` | não | ≤ 1000 (`TOO_LONG`) |

Campo obrigatório em falta → `REQUIRED`. Erros → 400 `VALIDATION_ERROR`.

Resolução do assunto (regras numeradas, no âmbito do cliente):

1. `POLICY`: `PolicyApi.view(policyId)`; não visível ou `policyholderUserId ≠ u` → 404 `COMPLAINT_SUBJECT_NOT_FOUND`. `insurer_id = view.insurerId`, `complainant_role = POLICYHOLDER`, `subject_label = view.number`, `broker_org_id = view.brokerOrgId`.
2. `CLAIM`: `ClaimApi.view(claimId)`; não visível → 404 `COMPLAINT_SUBJECT_NOT_FOUND`. `policy_id = view.policyId`; papel: se `reporterUserId = u`, `POLICYHOLDER → POLICYHOLDER`, `DRIVER → INSURED`, `THIRD_PARTY → THIRD_PARTY`; senão `POLICYHOLDER`. `subject_label = view.number`.
3. `PAYMENT`: `PaymentApi.intent(id)`; `payerUserId ≠ u` → 404 `COMPLAINT_SUBJECT_NOT_FOUND`. Papel `POLICYHOLDER`; `subject_label = view.reference`.
4. `BROKER`: como `POLICY`; `brokerOrgId` nulo → 400 `COMPLAINT_SUBJECT_INVALID`. `subject_id = broker_org_id`; `subject_label` = `displayName` do mediador (`ComplaintSystemLookups.organizationName`).
5. `SERVICE`/`OTHER` com `policyId`: como `POLICY`, mas `subject_id = null`.
6. `SERVICE`/`OTHER` sem `policyId`: `insurerId` tem de ser uma seguradora `ACTIVE` → senão 400 `COMPLAINT_INSURER_INVALID`; papel = `complainantRole`.
7. A seguradora estar suspensa não impede a reclamação nos casos 1–5.

Depois: número `RC`; prazos (secção 4); `insurer_name` e o e-mail de reclamações por `ComplaintSystemLookups.insurerSummary(insurerId)`; `complainant_*` de `IdentityApi.customer(u)`; `status = SUBMITTED`; `sla_due_at = ack_due_at`; auditoria; evento `ComplaintSubmitted`; avisos (secção 8).
