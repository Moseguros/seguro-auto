## Objectivo

`docker compose up` na pasta `infra/` sobe a base de dados, os serviços de apoio, o backend e a web; a web mostra a versão da API.

## Ficheiros

- `infra/docker-compose.yml`
- `infra/.env.example`
- `backend/Dockerfile`, `web/Dockerfile`, `web/nginx.conf`
- `infra/mocks/sms-mock/` (projecto Spring Boot mínimo, Maven, Java 17)
- `infra/README.md`

## Especificação

**Serviços do `docker-compose.yml`** (nomes exactos):

Todas as imagens com versão fixada (nunca `latest`). Todos os serviços têm `healthcheck` com o comando indicado (`interval: 10s`, `timeout: 5s`, `retries: 12`).

| Serviço | Imagem | Portas | Healthcheck | Notas |
| --- | --- | --- | --- | --- |
| `postgres` | `postgres:16-alpine` | 5432 | `pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}` | BD `moseguros`, utilizador e palavra-passe do `.env`; volume nomeado `pgdata` |
| `mailpit` | `axllent/mailpit:v1.33` | 1025 (SMTP), 8025 (web) | `["CMD", "/mailpit", "readyz"]` | SMTP de teste e interface web. Substitui o MailHog, que deixou de ser mantido |
| `sms-mock` | build `mocks/sms-mock` | 8090 | `curl -fsS http://localhost:8090/actuator/health` | ver abaixo |
| `backend` | build `../backend` | 8080 | o `HEALTHCHECK` do Dockerfile | perfil `local`; depende de `postgres` saudável; `DB_URL=jdbc:postgresql://postgres:5432/moseguros`; `SPRING_MAIL_HOST=mailpit`, `SPRING_MAIL_PORT=1025` |
| `web` | build `../web` | 3000 | `wget -qO /dev/null http://localhost:8080/` (porta interna do nginx) | nginx a servir o build e a fazer proxy de `/api` para `backend:8080`; depende de `backend` saudável |

**Armazenamento de ficheiros (S3):** não entra no Sprint 0, porque nada o usa ainda. A imagem `minio/minio` deixou de ser publicada no Docker Hub; a escolha do serviço S3 local faz-se na primeira tarefa que guarde ficheiros (Sprint 3).

RabbitMQ, SFTP, Vault e `mpesa-mock` entram no Sprint 5; não os adicionar agora.

**`backend/Dockerfile`**: multi-stage; build com `eclipse-temurin:17-jdk` e `./mvnw -B -DskipTests package`; runtime `eclipse-temurin:17-jre` com `curl` instalado (`apt-get install -y --no-install-recommends curl` e limpeza de `/var/lib/apt/lists`), utilizador não-root `app` (uid 10001), `JAVA_OPTS` por variável, `HEALTHCHECK CMD curl -fsS http://localhost:8080/api/v1/health || exit 1`. O `sms-mock` usa o mesmo padrão de Dockerfile.

**`web/Dockerfile`**: build com `node:20-alpine` + pnpm (`corepack enable`); runtime `nginxinc/nginx-unprivileged:1.27-alpine` (corre como não-root e escuta na porta 8080 interna; o compose publica `3000:8080`) com `nginx.conf` (fallback SPA para `index.html`, proxy `/api/` → `http://backend:8080/api/`, gzip, cache longa para `/assets/`).

**`sms-mock`**: aplicação Spring Boot com:
- `POST /sms` `{to, text}` → 202 `{id}`; guarda em memória (últimas 500).
- `GET /sms` → lista JSON (mais recente primeiro); `GET /` → página HTML simples com a mesma lista, actualizada a cada 3 s; `DELETE /sms` limpa.
- Será o alvo do `SmsSender` mock no Sprint 1.

- O `sms-mock` inclui `spring-boot-starter-actuator` (só `health` exposto).

**`.env.example`**: `POSTGRES_USER=moseguros`, `POSTGRES_PASSWORD=moseguros`, `POSTGRES_DB=moseguros`. O `docker-compose.yml` usa estes nomes com valores por defeito, para funcionar mesmo sem `.env`.

**`infra/README.md`**: como subir, URLs de cada serviço, como limpar volumes.

## Critérios de aceitação

- [ ] `cd infra && docker compose up -d --build` sobe todos os serviços; `docker compose ps` mostra-os saudáveis.
- [ ] `http://localhost:3000` mostra a versão da API (passa pelo nginx → backend).
- [ ] `http://localhost:8090` mostra a lista de SMS; `curl -X POST localhost:8090/sms -H 'content-type: application/json' -d '{"to":"+258841234567","text":"teste"}'` aparece na lista.
- [ ] Os contentores do backend e da web correm como utilizador não-root.

## Comandos de verificação

```bash
cd infra && docker compose up -d --build && docker compose ps
curl -fsS localhost:8080/api/v1/meta/version
curl -fsS localhost:3000/api/v1/meta/version
```
