## Contexto

Histórias 1 e 2 do Sprint 2 na web do cliente (`/cliente/veiculos`, `/cliente/condutores`). `AGENTS.md` §8: a mesma funcionalidade chega à app no S2-07, sobre os mesmos endpoints. Na web o livrete entra por envio de ficheiro ou pela câmara do browser (`capture`), sem câmara guiada (diferença permitida). O item de menu `vehicles` já existe (S0-05); esta tarefa substitui a página "Em construção".

**Pressupõe:** sessão, `RequireAuth({ type: 'CUSTOMER' })`, `http.ts`, `problem.ts` e o formulário de perfil com `getMyProfile` (S1-07); `menus.ts` e `AppLayout` (S0-05); `operationId`s do S2-01 (`downloadFile`), do S2-02 (`listReferenceValues`, `listActivePlateFormats`) e do S2-03 (`listMyVehicles`, `createMyVehicle`, `getMyVehicle`, `updateMyVehicle`, `deleteMyVehicle`, `uploadMyVehicleRegistrationDoc`, `updateMyVehicleDrivers`, `lookupVehicleRegistry`, `listMyDrivers`, `createMyDriver`, `getMyDriver`, `updateMyDriver`, `deleteMyDriver`); textos `vehicleCategory.*`, `vehicleUsage.*` (S2-02 §8) e `province.*` (S1-07); traduções dos códigos de erro de S2-01 e S2-03 (já no `main`).

## Objectivo

O cliente, num ecrã de 360 px, acrescenta um veículo (com pré-preenchimento a partir do registo para as matrículas de teste), envia a foto ou o PDF do livrete, regista condutores (incluindo ele próprio), escolhe o condutor habitual de cada veículo, altera e retira veículos e condutores.

## Especificação

### 1. Rotas (todas com `RequireAuth({ type: 'CUSTOMER' })`, layout `AppLayout` da área `cliente`)

| Rota | Página |
| --- | --- |
| `/cliente/veiculos` | lista de veículos |
| `/cliente/veiculos/novo` | acrescentar veículo |
| `/cliente/veiculos/:id` | detalhe (dados, livrete, condutores) |
| `/cliente/veiculos/:id/editar` | alterar veículo |
| `/cliente/condutores` | lista de condutores |
| `/cliente/condutores/novo` | registar condutor |
| `/cliente/condutores/:id/editar` | alterar condutor |

- `VehiclesTabs` no topo das duas listas: separadores "Veículos" e "Condutores" (ligações para as duas rotas). O item "Veículos" do menu fica marcado nas duas (`menuAliases`).
- 404 `VEHICLE_NOT_FOUND`/`DRIVER_NOT_FOUND` num detalhe → mensagem e ligação para a lista.

### 2. Lista de veículos (`/cliente/veiculos`)

- `listMyVehicles` (`size=50`, `sort=createdAt,desc`; com mais de 50 mostra "Ver mais").
- `VehicleCard` em grelha (1 coluna abaixo de 600 px, 2 até 1200, 3 acima): matrícula em destaque (`tabular-nums`), "{marca} {modelo} · {ano}", categoria (`vehicleCategory.*`), uso (`vehicleUsage.*`), condutor habitual ("Condutor habitual: {nome}" ou "Sem condutor habitual"), etiqueta de aviso "Livrete em falta" quando não há `registrationDoc`, etiqueta "Confirmado no registo" quando `inatroVerified`. Clique → detalhe.
- Botão primário azul "Acrescentar veículo" no cabeçalho.
- Estados: a carregar (3 esqueletos de cartão); vazio ("Ainda não registou nenhum veículo." com o mesmo botão); erro (mensagem traduzida e "Tentar de novo").
- **Nenhum botão laranja** nesta tarefa. O "Simular seguro" continua no início (`/cliente`, S1-07); a ligação do veículo à simulação chega no S3-04.

### 3. Formulário do veículo (`VehicleForm`, `react-hook-form` + `zod`)

Regras iguais às do S2-03 §2 (`vehicleSchema.ts`). Mensagens `validation.<CODE>`.

| Campo | Componente | Regras no browser |
| --- | --- | --- |
| Matrícula | texto, maiúsculas automáticas; ajuda "Ex.: {exemplos}" com os `example` de `listActivePlateFormats` separados por " ou " | obrigatório; ≤ 15 caracteres sem espaços nem hífens; o formato é validado pelo servidor (`INVALID_PLATE`) |
| (ao lado da matrícula) | `RegistryLookupButton` "Procurar no registo" | ver abaixo |
| N.º de chassis | texto, maiúsculas | `^[A-Z0-9]{5,30}$` depois de retirar espaços e hífens (`INVALID_CHASSIS`) |
| Marca | `Autocomplete` `freeSolo` com os `labelPt` de `VEHICLE_MAKE` | 1–60 |
| Modelo | `Autocomplete` `freeSolo`; opções de `VEHICLE_MODEL` com `parentCode` = código da marca, quando a marca escrita corresponde a um rótulo da lista | 1–60 |
| Ano | número, `inputMode="numeric"` | 1900 a `currentYearInMaputo() + 1` (`INVALID_YEAR`) |
| Categoria | select `vehicleCategory.*` | obrigatório |
| Cilindrada (cm³) | número; **escondido** em `TRAILER` (e enviado como ausente) | obrigatório nas outras; 1–30 000 |
| Lugares | número | `TRAILER` 0 (preenchido e desactivado); `MOTORCYCLE` 1–3; outras 1–100 |
| Peso bruto (kg) | número | obrigatório em `HEAVY` e `TRAILER`; opcional nas outras; 1–100 000 |
| Uso | select `vehicleUsage.*` | obrigatório |
| Província de circulação | select `province.*` | obrigatório |
| Valor comercial | `MoneyField`, opcional; ajuda "Necessário para seguros de danos próprios." | > 0 |
| Tem localizador (GPS) | interruptor | — |

- **`RegistryLookupButton`** → `lookupVehicleRegistry({ plate })`:
  - 200 → preenche chassis, marca, modelo, ano, cilindrada, categoria, lugares e peso (substitui o que lá estiver) e mostra o aviso informativo "Preenchemos os dados a partir do registo automóvel. Confirme-os com o seu livrete.";
  - 404 `VEHICLE_REGISTRY_NOT_FOUND` e 503 `VEHICLE_REGISTRY_UNAVAILABLE` → aviso com a mensagem do código; o formulário continua editável;
  - 400 → erro no campo matrícula.
- Botão primário "Guardar". Criar → `createMyVehicle` → detalhe do veículo com o aviso "Veículo acrescentado. Envie agora a foto do livrete." Alterar → `updateMyVehicle` com `version` → detalhe.
- Erros do servidor: de campo nos campos; `VEHICLE_ALREADY_REGISTERED` no campo matrícula; `VEHICLE_LIMIT_REACHED` em aviso no topo; `CONCURRENT_MODIFICATION` → "Este veículo foi alterado noutro dispositivo" com "Recarregar".
- A 360 px os campos ficam numa coluna; o botão "Procurar no registo" passa para baixo da matrícula.

### 4. Detalhe do veículo (`/cliente/veiculos/:id`)

- Cabeçalho: matrícula, "{marca} {modelo}", etiqueta "Confirmado no registo" ou "Não confirmado no registo" (neutra), botões "Alterar" (contorno) e "Retirar veículo" (texto vermelho; confirmação "O veículo deixa de aparecer na sua conta." → `deleteMyVehicle` → lista com o aviso "Veículo retirado"; `VEHICLE_REMOVAL_BLOCKED` (409, a partir do S6-01) → a mensagem do código na confirmação e o veículo fica).
- **Dados**: lista de pares rótulo/valor com todos os campos (valor comercial com `formatMoney`; ausentes "—").
- **Livrete** (`RegistrationDocSection`):
  - com documento de imagem JPEG ou PNG: miniatura (`useFileBlob` → `<img>` com largura máxima 100 %) e "Abrir";
  - com PDF ou HEIC (que os browsers não mostram): ícone do tipo, tamanho e "Abrir" (`FileOpenButton`);
  - sem documento: texto "Ainda não enviou o livrete.";
  - botões "Tirar foto" (`FileUploadButton` com `accept="image/*"` e `capture="environment"`) e "Escolher ficheiro" (`accept="image/jpeg,image/png,image/heic,application/pdf"`); com documento, os botões dizem "Substituir";
  - envio com `uploadMyVehicleRegistrationDoc` (`FormData` com `file`), barra de progresso, verificação de 10 MB e tipo no browser antes de enviar; sucesso → aviso "Livrete guardado" e actualiza o veículo; erros `FILE_*` com a mensagem do código.
- **Condutores**: lista dos condutores associados (nome, etiqueta "Habitual"); "Gerir condutores" → `ManageDriversDialog`:
  - caixas com os condutores do cliente (`listMyDrivers`) e, em cada caixa marcada, uma opção "Habitual" (só uma activa);
  - "Guardar" desactivado se houver condutores marcados e nenhum habitual (mensagem `validation.HABITUAL_DRIVER_REQUIRED`); no máximo 5;
  - `updateMyVehicleDrivers` com `version` do veículo;
  - sem condutores registados: texto "Ainda não registou condutores." e botão "Registar condutor" → `/cliente/condutores/novo?veiculo={id}` (depois de gravar, volta ao veículo e abre o diálogo).

### 5. Condutores

**Lista (`/cliente/condutores`)**: `DriverCard` com nome, etiqueta "Eu" quando `isOwner`, categorias (`labelPt` de `LICENCE_CATEGORY`, só o código quando não encontrado), carta mascarada (`licenceNumberMasked`), "{n} veículos"; menu "Alterar" e "Retirar" (confirmação; `DRIVER_IS_HABITUAL` → mensagem do código). Botão primário "Registar condutor". Estados a carregar, vazio ("Ainda não registou condutores.") e erro como na lista de veículos.

**Formulário (`DriverForm`)**, regras do S2-03 (`driverSchema.ts`):

| Campo | Componente | Regras |
| --- | --- | --- |
| Sou eu | interruptor; ao ligar, preenche nome e data de nascimento com `getMyProfile` (se existirem), que continuam editáveis; escondido se já houver outro condutor `isOwner` | — |
| Nome completo | texto | regras do S1-06 (`INVALID_NAME`) |
| Data de nascimento | `TextField type="date"`, `max = todayInMaputo()` | idade ≤ 100 (`INVALID_DATE`) |
| N.º da carta | texto, maiúsculas; ao alterar um condutor, mostra a máscara só de leitura com "Alterar" (abre o campo vazio; sem alteração envia `null`) | `^[A-Z0-9/-]{5,20}$` depois de retirar espaços (`INVALID_LICENCE_NUMBER`) |
| Categorias | caixas com os valores de `LICENCE_CATEGORY` (`listReferenceValues`) | pelo menos uma |
| Data de emissão da carta | `type="date"` | ≥ data de nascimento e ≤ hoje (`LICENCE_ISSUE_DATE_INVALID`) |

- Criar → `createMyDriver`; alterar → `updateMyDriver` com `version`. Erros `DRIVER_ALREADY_REGISTERED` (no campo da carta), `OWNER_DRIVER_ALREADY_EXISTS` (no interruptor), `DRIVER_LIMIT_REACHED` (aviso no topo).
- O número da carta em claro nunca é guardado no browser além do estado do formulário; não vai para `localStorage` nem para a cache do TanStack Query (a resposta só traz a máscara).

### 6. Textos

Chaves novas (`pt-MZ.json` e `en.json`): `vehicles.*`, `drivers.*` (títulos, rótulos, ajudas, avisos e confirmações citados acima, com o texto pt exacto da ficha), mais `vehicleCategory.*` e `vehicleUsage.*` do S2-02 §8 se ainda não existirem (o S2-05 pode tê-las criado). Nenhum texto directamente nos componentes.
