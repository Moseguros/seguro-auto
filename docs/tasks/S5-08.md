## Contexto

Os pagamentos por entidade e referência são confirmados por ficheiros que cada seguradora recebe no seu SFTP (ADR-004). O `payment-file-worker` (S5-09) lê-os com um `PaymentFileParser` escolhido por `settings.fileFormat` da fonte. O layout real do ficheiro é fornecido pelo proprietário do produto; **não se inventa layout** (`AGENTS.md` §9 regra 8).

Esta ficha tem duas partes:

- **§2 e §3 — contrato, validação comum e parser fake.** Não estão bloqueados: são implementados pelo **S5-09** (no projecto `payment-file-worker`), que remete para aqui.
- **§4 — o parser real.** É o que esta tarefa entrega quando for desbloqueada. Depende também do S5-09 estar no `main` (o projecto do worker é criado lá).

**Pressupõe:** S5-06 (`payment-contracts`, RabbitMQ, SFTP local); S5-09 (projecto `payment-file-worker`, `FileValidator`, `ParserRegistry`); S5-01 (`settings.fileFormat`, `settings.entity`, `settings.timezone`).

## Objectivo

## 1. O que pedir ao proprietário do produto (antes de escrever código)

Quem chegar a esta tarefa **pára** e envia este pedido (registar a data em "Questões"):

1. **Especificação escrita do ficheiro**, de fonte oficial (SIMO ou banco):
   - codificação de caracteres (UTF-8, ISO-8859-1, …) e terminador de linha;
   - largura fixa ou separador (qual);
   - **cabeçalho**: campos, posições ou ordem, e o que identifica a entidade e a data do ficheiro;
   - **registos de detalhe**: entidade, referência, montante, data e hora do pagamento, canal ou terminal, identificador único da transacção do banco, outros campos;
   - **rodapé**: número de registos, montante total, outros controlos;
   - formato das **datas e horas** e o fuso em que vêm;
   - formato dos **valores**: casas decimais, separador, sinal, zeros à esquerda;
   - se há registos de **estorno ou correcção** (montantes negativos, tipos de registo);
   - nome dos ficheiros (padrão, data no nome), um ou vários por dia, ficheiros vazios;
   - compressão ou cifra (ZIP, PGP) e assinatura, se houver.
2. **Ficheiros de exemplo anonimizados**: pelo menos um ficheiro válido com 20 ou mais registos, um ficheiro vazio (se existir) e um ficheiro com um erro conhecido (rodapé errado ou linha mal formada), com o resultado esperado de cada registo.
3. **Operação**: quem coloca os ficheiros no SFTP de cada seguradora, com que frequência, se o mesmo ficheiro pode ser reenviado, e quanto tempo ficam no servidor.

Até haver resposta, esta parte **não avança**. O worker funciona com o parser fake em `local` e `test`.

## 2. Contrato (implementado no S5-09)

Pacote `mz.co.moseguros.paymentworker.parser` do projecto `payment-file-worker`:

```java
public interface PaymentFileParser {
  String format();            // valor de settings.fileFormat, ex.: "FAKE_SIMO_V0"
  boolean isFake();
  ParsedFile parse(InputStream in, ParseContext ctx) throws PaymentFileParseException;
}
public record ParseContext(String sourceEntity, ZoneId zone, String fileName) {}
public record ParsedFile(FileHeader header, List<ParsedRecord> records, FileTrailer trailer) {}
public record FileHeader(String entity, LocalDate fileDate, String rawHeader) {}
public record ParsedRecord(int lineNo, String entity, String reference, long amountCentavos,
    Instant paidAt, String channel /* pode ser null */, String bankTransactionId /* null se o ficheiro não tiver */,
    String rawLine) {}
public record FileTrailer(int recordCount, long totalAmountCentavos) {}
public class PaymentFileParseException extends Exception {   // code: PARSE_ERROR, ENCODING_ERROR, MISSING_HEADER, MISSING_TRAILER
  public PaymentFileParseException(String code, Integer lineNo, String message) { … }
}
```

- O S5-08 pode **acrescentar** campos a `ParsedRecord` e `FileHeader` se o layout real os tiver; não muda os existentes.
- `ParserRegistry`: mapa `format → parser`; dois com o mesmo nome → falha no arranque.

**Validação comum (`FileValidator`, S5-09), igual para todos os parsers**, depois do `parse`:

| Regra | Código de rejeição |
| --- | --- |
| `header.entity ≠ fonte.entity` | `ENTITY_MISMATCH` |
| algum `record.entity ≠ header.entity` | `ENTITY_MISMATCH` |
| `trailer.recordCount ≠ records.size()` | `TRAILER_COUNT_MISMATCH` |
| `trailer.totalAmountCentavos ≠ Σ amountCentavos` | `TRAILER_TOTAL_MISMATCH` |
| algum `amountCentavos ≤ 0` | `INVALID_AMOUNT` |
| `lineNo` repetido | `PARSE_ERROR` |

Uma falha rejeita o ficheiro inteiro (nenhum registo é publicado).

## 3. Parser fake (implementado no S5-09)

**`FakeSimoFileParser`** — `@Profile({"local","test"})`, `format() = "FAKE_SIMO_V0"`, `isFake() = true`.

> **Formato inventado só para testes e desenvolvimento. Não tem nenhuma relação com o layout real da SIMO e nunca pode ser usado com dinheiro real.** Escrever este aviso no Javadoc da classe e no início de cada ficheiro de exemplo (linha de comentário `#`).

- UTF-8; linhas terminadas em `\n` ou `\r\n`; linhas vazias e linhas começadas por `#` são ignoradas (mas contam para `lineNo`); separador `;`.
- Cabeçalho (primeira linha útil): `H;FAKE_SIMO_V0;<entity>;<yyyyMMdd>`.
- Detalhe: `D;<reference>;<montante em centavos>;<yyyy-MM-dd'T'HH:mm:ss na zona da fonte>;<canal>;<bankTransactionId>` — canal em `ATM`, `BANK`, `INTERNET`, `MOBILE`; `bankTransactionId` pode ser vazio (→ `null`).
- Rodapé (última linha útil): `T;<número de registos D>;<total em centavos>`.
- Erros: sem `H` → `MISSING_HEADER`; sem `T` → `MISSING_TRAILER`; campo em falta, número inválido ou data inválida → `PARSE_ERROR` com `lineNo`; bytes não UTF-8 → `ENCODING_ERROR`.

Exemplo (`infra/mocks/sftp/samples/FAKE_SIMO_V0-exemplo.txt`, S5-09):

```
# FORMATO INVENTADO SÓ PARA TESTES — NÃO É O LAYOUT SIMO
H;FAKE_SIMO_V0;90001;20270115
D;999004217;299900;2027-01-15T09:12:44;ATM;BT0000001
D;999118230;150000;2027-01-15T10:01:02;INTERNET;
T;2;449900
```

**Recusa de arranque do worker:** com perfis que não incluam `local` nem `test`, se o `ParserRegistry` só tiver parsers fake, o worker **não arranca** (mensagem: `Sem parser SIMO real (tarefa S5-08 bloqueada)`). Uma fonte cujo `fileFormat` não tenha parser registado é ignorada com `ERROR` no log e publica `PaymentSourcePolled` com `outcome = ERROR`, `errorCode = UNSUPPORTED_FORMAT` (S5-09).

### Ficheiros a criar ou alterar

- `docs/adr/ADR-004-worker-ficheiros-rabbitmq.md` — secção "Pendente" e `docs/STATUS.md`, como no S5-07

### Especificação

- `SimoFileParser implements PaymentFileParser`, `isFake() = false`, sem `@Profile`.
- Lê **exactamente** o layout recebido; qualquer ponto que a especificação não esclareça vai para "Questões" e a tarefa pára nesse ponto.
- Converte datas para `Instant` com o fuso que a especificação indicar (ou `ParseContext.zone`, se a especificação disser que é a hora local).
- Converte valores para centavos sem perda (`BigDecimal`, sem `double`).
- Se o ficheiro não tiver identificador único da transacção, `bankTransactionId = null` e o `messageId` usa a regra alternativa do S5-06.
- Registos de estorno ou correcção, se existirem: não se publicam como pagamentos; o ficheiro é rejeitado com `UNSUPPORTED_RECORD` até haver uma regra de negócio (pergunta ao proprietário do produto).
- Ficheiros comprimidos ou cifrados: só se a especificação os previr; a chave fica no cofre como um segredo novo da fonte (acrescentar a `SecretField` no S5-01, nesta tarefa).

### Critérios de aceitação

- [ ] `SimoFileParserTest`: cada exemplo válido dá exactamente os registos de `expected.csv`; o exemplo com erro dá o código de rejeição esperado.
- [ ] `FileProcessingIT` do S5-09 passa com o ficheiro real anonimizado (Testcontainers com SFTP e RabbitMQ): os registos chegam ao RabbitMQ e o ficheiro vai para `processedDir`; o ficheiro com erro vai para `errorDir`.
- [ ] Com o perfil `prod`, o worker arranca.
