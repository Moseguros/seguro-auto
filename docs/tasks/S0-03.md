## Especificação

Todos os value objects são `record` imutáveis, validam no construtor compacto e lançam `DomainException` com `code` indicado, status 400.

**Money** — `record Money(long amount, String currency)`: `amount` em centavos; `currency` sempre `"MZN"` (outro → `INVALID_CURRENCY`). Fábricas `Money.ofCentavos(long)`, `Money.ofMeticais(BigDecimal)` (arredonda HALF_UP a 2 casas; mais de 2 casas → arredonda), `Money.zero()`. Operações `plus`, `minus`, `times(BigDecimal)` (HALF_UP), `isNegative`, `compareTo`. JSON: `{"amount": 299900, "currency": "MZN"}`.

**Msisdn** — telemóvel moçambicano. Aceita `+258841234567`, `258841234567`, `841234567`, com espaços ou hífens. Normaliza para `258` + 9 dígitos. O número nacional tem 9 dígitos, começa por `8` e o segundo dígito está entre `2` e `7` (82–87). Senão `INVALID_MSISDN`. Métodos `e164()` → `+258841234567`, `national()` → `841234567`, `masked()` → `+258*****4567`. JSON: string E.164.

A máscara é **a mesma em todo o sistema** (logs, ecrãs, mensagens): os últimos 4 dígitos visíveis, igual ao `SensitiveDataMasker` do S0-02. Um teste prova que `SensitiveDataMasker.mask(m.e164())` é igual a `m.masked()`.

**Nuit** — exactamente 9 dígitos após remover espaços; senão `INVALID_NUIT`. **Sem dígito de controlo** (decisão de 31/10/2026: não há algoritmo publicado em fonte oficial). `masked()` → `*****6789`.

**Matricula** — os formatos aceites são **configuráveis**, não estão no código.

- `record PlateFormat(String code, String label, Pattern pattern, String displayTemplate, boolean active)`: `pattern` é aplicado ao valor normalizado (maiúsculas, sem espaços nem hífens) e tem grupos nomeados; `displayTemplate` reconstrói o valor formatado a partir dos grupos (ex.: `${l}-${n}-${p}`).
- Interface `PlateFormatProvider { List<PlateFormat> activeFormats(); }`. Nesta tarefa a implementação `ConfigPlateFormatProvider` lê `moseguros.plates.formats` do `application.yml`. No Sprint 2 passa a ler da tabela `catalog.plate_format`, editável em `/admin/referencias` sem novo deploy; o resto do código não muda.
- `Matricula` guarda o valor formatado e o `formatCode`. Criação só por `PlateParser.parse(String raw)` (componente Spring que usa o provider): normaliza, testa os formatos activos por ordem, e o primeiro que corresponder define o formato; nenhum → `INVALID_PLATE`. `Matricula.restore(value, formatCode)` serve para ler da BD sem validar de novo.
- `masked()` substitui por `*` todos os dígitos do valor formatado (`ABC-***-MC`).
- Formatos iniciais no `application.yml`:

```yaml
moseguros:
  plates:
    formats:
      - code: STANDARD
        label: Actual (ABC-123-MC)
        pattern: '^(?<l>[A-Z]{3})(?<n>\d{3})(?<p>[A-Z]{2})$'
        display-template: '${l}-${n}-${p}'
      - code: LEGACY
        label: Antigo (ABC-12-34)
        pattern: '^(?<l>[A-Z]{3})(?<a>\d{2})(?<b>\d{2})$'
        display-template: '${l}-${a}-${b}'
```

- JSON: string formatada. Na desserialização de pedidos usa-se o `PlateParser` (deserializador Jackson registado como bean).

**Ids** — `Ids.newId()` devolve UUID v7 (usar `com.github.f4b6a3:uuid-creator`, `UuidCreator.getTimeOrderedEpoch()`).

**BaseEntity** — `@MappedSuperclass` com `id UUID` (atribuído por `Ids.newId()` no construtor, não gerado pela BD), `createdAt`, `createdBy`, `updatedAt`, `updatedBy` (Spring Data auditing: `@CreatedDate`, `@CreatedBy`, `@LastModifiedDate`, `@LastModifiedBy`), `version long` com `@Version`. `equals`/`hashCode` por `id`. Activar `@EnableJpaAuditing` com `AuditorAware<String>` que devolve o `sub` do utilizador autenticado ou `"system"`.

**Migração** `V202610311200__shared_schemas_e_auditoria.sql`:
- `create schema if not exists` para: `audit, identity, organization, vehicle, catalog, rating, proposal, payment, policy, document, notification, verification, claim, complaint, assistance, reporting, fraud, integration`.
- Tabela:

```sql
create table audit.audit_event (
  id           uuid primary key,
  occurred_at  timestamptz not null,
  actor_id     varchar(64) not null,
  actor_type   varchar(20) not null check (actor_type in ('CUSTOMER','STAFF','SYSTEM','SERVICE')),
  insurer_id   uuid null,
  action       varchar(80) not null,
  entity_type  varchar(60) not null,
  entity_id    varchar(64) not null,
  before_state jsonb null,
  after_state  jsonb null,
  ip           varchar(45) null,
  trace_id     varchar(64) null
);
create index ix_audit_entity on audit.audit_event (entity_type, entity_id, occurred_at desc);
create index ix_audit_insurer on audit.audit_event (insurer_id, occurred_at desc);
```

- Configurar `spring.flyway.schemas` não é necessário; a migração cria os schemas. `spring.flyway.default-schema: public` mantém o histórico do Flyway em `public`.
- **Excepção às colunas obrigatórias do `AGENTS.md` §5:** `audit.audit_event` só recebe inserções (nunca é alterada nem apagada), por isso não tem `created_by`, `updated_at`, `updated_by` nem `version`; `occurred_at` e `actor_id` fazem esse papel. `AuditEvent` **não** estende `BaseEntity`. Esta é a única excepção; está também escrita no `AGENTS.md`.

**AuditService** — `record(AuditRecord r)` grava um evento; usado nas tarefas seguintes. Nesta tarefa só se cria e testa. O papel de BD só-de-inserção na tabela fica para o Sprint 11.

```java
public record AuditRecord(
    ActorType actorType,          // enum CUSTOMER, STAFF, SYSTEM, SERVICE (obrigatório)
    String actorId,               // sub do utilizador, ou nome do job/serviço (obrigatório, ≤ 64)
    UUID insurerId,               // null quando não se aplica
    String action,                // verbo em maiúsculas com ponto: "POLICY.ISSUE", "OTP_SETTINGS.UPDATE" (obrigatório, ≤ 80)
    String entityType,            // nome da entidade: "Policy", "OtpSettings" (obrigatório, ≤ 60)
    String entityId,              // id da entidade em texto (obrigatório, ≤ 64)
    Object beforeState,           // null na criação; serializado para JSONB com o ObjectMapper da aplicação
    Object afterState             // null na eliminação lógica; idem
) {}
```

- `AuditService.record` preenche sozinho `id` (`Ids.newId()`), `occurred_at` (relógio `Clock` injectado, UTC), `ip` (do pedido HTTP actual, se existir; primeiro valor de `X-Forwarded-For` ou o endereço remoto) e `trace_id` (do MDC `traceId`, se existir).
- `beforeState`/`afterState` são gravados tal como o objecto serializado, sem passar pelo `SensitiveDataMasker`. Quem chama é responsável por não lá pôr segredos nem documentos em claro: usa um DTO de auditoria com os valores já mascarados.
- Corre na transacção de quem chama (`Propagation.MANDATORY`): se a operação falhar, o evento de auditoria também não fica.
