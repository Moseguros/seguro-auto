# S0-08 — Integração contínua (GitHub Actions)

| Campo | Valor |
| --- | --- |
| Sprint | S0 |
| Depende de | S0-03 a S0-07 |
| Branch | `task/S0-08-ci` |
| Estado | pronta |

## Objectivo

Cada pull request corre automaticamente os builds e testes das partes que alterou, e falha se o contrato OpenAPI estiver desactualizado.

## Ficheiros

- `.github/workflows/backend.yml`
- `.github/workflows/web.yml`
- `.github/workflows/mobile.yml`
- `.github/workflows/contract.yml`
- `.github/workflows/infra.yml`
- `.github/pull_request_template.md`
- `.github/CODEOWNERS`

## Especificação

Todos os workflows: `on: pull_request` e `push` para `main`; `concurrency` por branch com `cancel-in-progress: true`; `permissions: contents: read`; filtros `paths` como abaixo; runners `ubuntu-latest`.

| Workflow | `paths` | Passos |
| --- | --- | --- |
| `backend.yml` | `backend/**`, `.github/workflows/backend.yml` | `actions/setup-java@v4` (Temurin 17, cache maven) → `./mvnw -B verify` (Testcontainers usa o Docker do runner) → publicar relatório JaCoCo e relatórios de testes como artefactos |
| `contract.yml` | `backend/**`, `api/**` | Java 17 → `./scripts/check-openapi.sh` → `npx --yes @redocly/cli lint api/openapi.yaml` |
| `web.yml` | `web/**`, `api/**` | `pnpm/action-setup@v4` (pnpm 9) → `actions/setup-node@v4` (`node-version-file: web/.nvmrc`, cache pnpm) → `pnpm install --frozen-lockfile` → `pnpm api:generate` → `git diff --exit-code web/src/api` → `lint`, `typecheck`, `test`, `build` → `npx playwright install --with-deps chromium` → `test:e2e` → artefacto do relatório Playwright em falha |
| `mobile.yml` | `mobile/**`, `api/**` | `subosito/flutter-action@v2` (`flutter-version-file: mobile/pubspec.yaml`, cache; a versão é a fixada no S0-06) → Java 17 → `./tool/generate_api.sh` → `git diff --exit-code mobile/packages/moseguros_api` → `flutter pub get` → `flutter analyze` → `flutter test` → `flutter build apk --flavor dev -t lib/main_dev.dart --debug` → APK como artefacto |
| `infra.yml` | `infra/**`, `backend/**`, `web/**` | `docker compose -f infra/docker-compose.yml config` → `docker compose up -d --build` → esperar saúde (máx. 3 min) → `curl` aos dois endpoints de versão → `docker compose down -v` |

**`pull_request_template.md`**: secções "Tarefa" (ID e link da ficha), "O que foi feito", "Como testar", "Critérios de aceitação" (lista para marcar), "Fora do âmbito", "Questões".

**`CODEOWNERS`**: `* @edmilson-alar`.

## Critérios de aceitação

- [ ] Um PR que só altere `web/` corre `web.yml` e `infra.yml`, e não corre `backend.yml`, `mobile.yml` nem `contract.yml`.
- [ ] Todos os workflows passam no estado do `main` depois de S0-02 a S0-07.
- [ ] Alterar `api/openapi.yaml` à mão faz falhar `contract.yml`.
- [ ] Alterar um endpoint sem regenerar os clientes faz falhar `web.yml` e `mobile.yml`.

## Comandos de verificação

Abrir o PR e confirmar os checks no GitHub. Localmente, cada passo dos workflows pode ser repetido com os comandos das fichas S0-02 a S0-07.

## Fora do âmbito

Deploy para ambientes, assinatura de builds móveis, testes de carga.
