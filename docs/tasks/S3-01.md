## Contexto

Primeira tarefa do Sprint 3 (Motor tarifário e cotações; RF-03 e RF-15, parte de tarifação). Define o formato da tarifa interna de cada versão de produto, a sua validação, o cálculo exacto do prémio (com arredondamentos) e os encargos (impostos e taxas) de cada seguradora. A S3-02 usa o avaliador para cotar e simular; a S3-03 constrói o editor sobre os endpoints desta tarefa.

ADR-001 (módulo `rating`), ADR-002 (isolamento por seguradora), ADR-006 (sentido das dependências: `rating → catalog, vehicle, organization, identity`). Modelo transversal §2 (`organization.insurer_profile` ganha `rating_mode`, `rating_endpoint_url`, `rating_secret_ref`, `charges`), §3 (`OrganizationApi.insurerProfile`), §5 (permissões do S3), §6 (carimbos `20261215HHmm`).

**Pressupõe:**

## Objectivo

Uma versão de produto em rascunho pode receber uma tarifa interna validada por JSON Schema e por regras de negócio; a seguradora configura os seus encargos; e o `TariffEvaluator` calcula, para os 10 casos de `docs/tasks/S3-rating-cases.md`, exactamente os valores escritos nesse ficheiro.

### 5. Tarifa de uma versão de produto (módulo `rating`, tag `Rating`)

A tarifa vive em `catalog.product_version.rules.rating`. O `CatalogApi.version` do S2-04 só lê versões publicadas, e o editor trabalha sobre rascunhos. Por isso esta tarefa acrescenta ao `CatalogApi` (modelo transversal §3: as fichas podem acrescentar métodos):

```java
/** Qualquer estado, no âmbito de quem chama (RLS: só a seguradora dona). Não visível → PRODUCT_VERSION_NOT_FOUND. */
ProductVersionView insurerVersion(UUID productVersionId);

/** Grava rules.rating de uma versão DRAFT. Devolve a nova version. */
long updateRatingRules(UUID productVersionId, JsonNode rating, long expectedVersion);
```

- `insurerVersion` **não** usa o `CatalogSystemLookups`: lê pelo repositório normal, e o RLS mostra só as versões da seguradora do `TenantContext`.
- `updateRatingRules` só aceita versões `DRAFT` (senão 409 `PRODUCT_VERSION_NOT_EDITABLE`), confirma `expectedVersion` (senão 409 `CONCURRENT_MODIFICATION`), substitui só a chave `rating` de `rules` (`rules = rules || {"rating": …}`) e incrementa `version`. Não valida o conteúdo: isso é do `rating`.
- O `rating` lê a versão com `insurerVersion` nos três endpoints abaixo.

**`GET /api/v1/insurer/product-versions/{id}/rating`** (`getRatingRules`), `hasAnyAuthority('rating:manage','product:read')` → 200:

```json
{
  "productVersionId": "0193…",
  "productType": "COMPREHENSIVE",
  "editable": true,
  "configured": true,
  "rating": { "schemaVersion": "rating-v1", "coverages": [ … ] },
  "coverages": [
    { "code": "MTPL", "mandatory": true, "capitalType": "FIXED", "capital": { "amount": 300000000, "currency": "MZN" }, "capitalOptions": null },
    { "code": "VTPL", "mandatory": false, "capitalType": "OPTIONS", "capital": null,
      "capitalOptions": [ { "amount": 500000000, "currency": "MZN" }, { "amount": 1000000000, "currency": "MZN" } ] }
  ],
  "version": 7
}
```

- `editable = status == DRAFT`; `configured = rules.rating != null`; `rating` é `null` quando não está configurada.
- Uma versão nova criada a partir de uma publicada (`createProductVersion`, S2-04) já traz a tarifa da anterior, porque o S2-04 copia `rules`.
- `coverages` repete as coberturas da versão (para o editor saber que tabelas tem de mostrar).

**`PUT /api/v1/insurer/product-versions/{id}/rating`** (`updateRatingRules`), `rating:manage`, corpo `{ "rating": { … }, "version": 7 }` → 200, mesma resposta.
- Corpo com mais de 262 144 bytes → 400 `RATING_RULES_TOO_LARGE` (verificado pelo `Content-Length` e pelo tamanho lido).
- Validação: secção 6 (schema) e depois secção 7 (regras). Qualquer erro → 400 `VALIDATION_ERROR` com `errors[]`, onde `field` é o ponteiro JSON dentro de `rating` (ex.: `/coverages/0/factors/1/rows/2/when/driverAgeYears`) e `code` um dos códigos de campo da secção 11. Os erros de schema usam `SCHEMA_VIOLATION`, com a mensagem do validador em `message`.
- A tarifa é gravada como chegou (normalizada pelo Jackson; sem reordenar linhas).
- Auditoria `RATING_RULES.UPDATE`, entidade `ProductVersion`, antes e depois = o JSON da tarifa (não tem dados pessoais).

**`POST /api/v1/insurer/product-versions/{id}/rating/validate`** (`validateRatingRules`), `rating:manage`, corpo `{ "rating": { … } }` → 200 `{ "valid": false, "errors": [ { "field": "/coverages/0/base/rows/3/value", "code": "VALUE_OUT_OF_RANGE", "message": "…" } ] }`. Não grava. Serve o editor e a importação CSV (S3-03). Funciona também em versões `PUBLISHED`.

Erros comuns aos três: versão não visível → 404 `PRODUCT_VERSION_NOT_FOUND`; cliente ou mediador → 403.

### 7. Regras de validação da tarifa (`RatingRulesValidator`, depois do schema)

Cada regra devolve um erro de campo com o ponteiro do elemento em causa. Validam-se todas e devolvem-se todos os erros (não pára no primeiro).

1. Cada cobertura da versão tem exactamente uma entrada em `coverages` → senão `COVERAGE_TARIFF_MISSING` (ponteiro `/coverages`, `message` com o código).
2. Uma entrada cujo `coverageCode` não existe na versão → `COVERAGE_NOT_IN_PRODUCT`; repetida → `DUPLICATE_COVERAGE`.
3. Tipo da base por tipo de capital da cobertura (`BASE_TYPE_NOT_ALLOWED`):
   - `AMOUNT`: qualquer;
   - `RATE_OF_VEHICLE_VALUE`: só `VEHICLE_VALUE`;
   - `RATE_OF_CAPITAL`: só `FIXED`, `OPTIONS`, `PER_PERSON`.
4. Valores (`VALUE_OUT_OF_RANGE`):
   - linha da base `RATE_OF_*`: `0 < value ≤ 1`;
   - linha de factor: `0 < value ≤ 100`;
   - `durationFactors[].factor`: `0 < factor ≤ 1`.
5. Intervalos: `gte` e `lt` presentes juntos com `gte ≥ lt` → `INVALID_RANGE`.
6. `code` de factor repetido na mesma cobertura → `DUPLICATE_FACTOR`; `BONUS_MALUS` é reservado ao S7 → `RESERVED_FACTOR_CODE`.
7. Duração:
   - `days` repetido → `DUPLICATE_DURATION`;
   - entrada com `days = 365` e `factor` diferente de 1 (comparação numérica: `"1"`, `"1.0"` e `"1.000000"` são 1) → `DURATION_365_NOT_ONE`;
   - produto `TEMPORARY` sem `durationFactors` → `DURATION_FACTORS_REQUIRED`;
   - produto que não é `TEMPORARY` com uma entrada de `days ≠ 365` → `DURATION_NOT_ALLOWED`.
8. Tarifa com mais de 262 144 bytes → 400 `RATING_RULES_TOO_LARGE` (código de topo, antes de qualquer outra validação).

Linhas que nunca se aplicam (porque uma anterior apanha sempre) não são erro.

### 8. Variáveis de tarifação (`RatingVariables`)

Calculadas uma vez por cotação a partir de `RatedVehicle`, `RatedDriver`, da data de início `D` (data local, sem hora) e da duração.

```java
public record RatedVehicle(UUID vehicleId, String plate, String make, String model, int year, Integer engineCc,
                           VehicleCategory category, VehicleUsage usage, Integer seats, Integer grossWeightKg,
```

`commercialValue` em centavos (o `Money` do `VehicleSnapshot` convertido com `amount()`).

| Variável | Tipo | Valor |
| --- | --- | --- |
| `vehicleCategory` | enum | `vehicle.category` |
| `vehicleUsage` | enum | `vehicle.usage` |
| `province` | enum | `vehicle.provinceOfCirculation` |
| `hasTracker` | booleano | `vehicle.hasTracker` |
| `vehicleAgeYears` | inteiro | `max(0, D.getYear() − vehicle.year)` |
| `engineCc`, `seats`, `grossWeightKg` | inteiro | do veículo; ausente se `null` |
| `driverAgeYears` | inteiro | `max(0, Period.between(driver.birthDate, D).getYears())`; ausente se `birthDate` for `null` |
| `licenceYears` | inteiro | `max(0, Period.between(driver.licenceIssueDate, D).getYears())`; ausente se `null` |
| `durationDays` | inteiro | duração pedida |
| `vehicleValue` | centavos | `vehicle.commercialValue`; ausente se `null` |
| `capital` | centavos | capital resolvido **da cobertura que está a ser avaliada** (regra 9.4) |

- As idades contam-se na data de início `D`, não na data de hoje. Quem faz 25 anos no próprio dia `D` tem 25.
- Uma condição sobre uma variável ausente **não** se cumpre.

### 9. Avaliação (`CoverageSelector` + `TariffEvaluator`)

Entrada: `RatingInput(productType, requestedCoverages: List<RequestedCoverage(code, Long capital)>, vehicle, driver, startDate, durationDays)`, `ProductDefinition` (coberturas da versão, por ordem), a tarifa (`RatingRules`, pode ser `null`) e os encargos (`List<ChargeRule>`). Saída: `EvaluationResult`, que é `Offered(PremiumBreakdown)` ou `Unavailable(UnavailableReason, Map<String,Object> detail)`.

O `CoverageSelector` é separado do avaliador porque a tarifação externa (S3-02) também o usa.

**Selecção das coberturas (`CoverageSelector`)** — pára no primeiro problema:

1. `S` = coberturas obrigatórias da versão ∪ códigos pedidos.
2. Código pedido que a versão não tem → `COVERAGE_NOT_OFFERED`, `detail = { "codes": [...] }`.
3. Para cada cobertura de `S`, os seus `requiresCodes` têm de estar em `S` → senão `COVERAGE_REQUIREMENTS_NOT_MET`, `detail = { "coverageCode", "missing": [...] }`.
4. Capital de cada cobertura:
   - `FIXED` e `PER_PERSON` → `CoverageView.capital` (em `PER_PERSON` é o capital por pessoa); o capital pedido é ignorado;
   - `VEHICLE_VALUE` → `vehicle.commercialValue` (`null` → `VEHICLE_VALUE_REQUIRED`);
   - `OPTIONS` → sem capital pedido, o menor de `capitalOptions`; com capital pedido, o menor valor de `capitalOptions` que seja `≥` ao pedido; nenhum → `CAPITAL_NOT_OFFERED`, `detail = { "coverageCode", "requested", "maxOffered" }`.
5. Ordem: a das coberturas da versão.

**Tarifa (`TariffEvaluator`)**:

1. `rules.rating` ausente → `TARIFF_MISSING`. Tarifa que não se consegue ler (não devia acontecer, foi validada ao gravar) → `TARIFF_INVALID`.
2. Factor de duração `fd`: a entrada de `durationFactors` com `days = durationDays`; sem entrada e `durationDays = 365` → `fd = 1`; sem entrada noutra duração → `DURATION_NOT_RATED`.
3. Para cada cobertura `c` de `S`, pela ordem:
   1. Linha da base: a **primeira** linha cujas condições se cumprem todas. Nenhuma → `NO_MATCHING_ROW`, `detail = { "coverageCode": c, "table": "BASE" }`.
   2. Valor base `B` (em centavos, `BigDecimal` exacto):
      - `AMOUNT` → `value`;
      - `RATE_OF_VEHICLE_VALUE` → `vehicleValue × value`;
      - `RATE_OF_CAPITAL` → `capital(c) × value`.
   3. Para cada tabela de factores, pela ordem: a primeira linha que se cumpre dá `fᵢ`. Nenhuma → `NO_MATCHING_ROW`, `detail = { "coverageCode": c, "table": <code do factor> }`.
   4. Factor bónus/malus `fbm = 1` (sempre, até ao S7; aparece na decomposição).
   5. Prémio exacto `Pₑ = B × Π fᵢ × fbm × fd`, em `BigDecimal` **sem arredondamentos intermédios** (as multiplicações de `BigDecimal` são exactas).
   6. Prémio da cobertura `P(c) = Pₑ.setScale(0, RoundingMode.HALF_UP)` (centavos inteiros).
4. A primeira cobertura que falhe torna toda a cotação `Unavailable`; não se devolvem preços parciais.
5. Prémio comercial `PC = Σ P(c)`.
6. Encargos (`ChargeCalculator`), pela ordem configurada, todos sobre `PC` (não há encargo sobre encargo):
   - `PERCENT` → `(PC × percent / 100).setScale(0, HALF_UP)`;
   - `FIXED` → o valor.
7. Subtotal `ST = PC + Σ encargos`.
8. Total `T = ⌈ST / 100⌉ × 100`: arredondar **para cima** ao metical inteiro (plano, Sprint 3). Ajuste de arredondamento `A = T − ST` (0 a 99 centavos).
9. Um mesmo pedido avaliado duas vezes dá sempre o mesmo resultado (nada depende da hora actual, só de `D`).

### 11. `UnavailableReason` (pacote raiz do `rating`, público)

Os quatro `INSURER_*`/`EXTERNAL_*` e `EVALUATION_ERROR` são usados pela S3-02; ficam já aqui para a lista ser uma só.
