## Objectivo

Depois de fotografar o livrete ou o documento, a app mostra os dados que conseguiu ler numa folha de revisão; o cliente corrige, escolhe o que usar e confirma; só então os campos do formulário ficam preenchidos. Se a leitura falhar, o cliente preenche à mão como antes.

## Especificação

### 1. Reconhecimento

- `TextRecognizerService` (interface): `Future<RecognizedText> recognize(String imagePath)`; `RecognizedText` = lista de linhas `{ text, boundingBox, blockIndex }` por ordem de leitura (de cima para baixo, da esquerda para a direita).
- `MlKitTextRecognizer`: `TextRecognizer(script: TextRecognitionScript.latin)`, `InputImage.fromFilePath`. Modelo incluído na app (funciona sem rede). Fecha o reconhecedor no `dispose` do provider.
- Corre sobre o ficheiro já tirado pela câmara do S2-07/S4-09, antes ou em paralelo com o envio da foto; não muda o envio.
- Timeout de 5 s. Erro ou timeout → `SnackBar` `ocrUnreadable` e o formulário fica como estava.
- O texto reconhecido e os valores lidos **nunca** são registados em log, guardados em disco, nem enviados à API ou a qualquer serviço.

### 2. Normalização comum

Antes de procurar valores, cada linha é normalizada para comparação: maiúsculas, sem acentos, espaços múltiplos colapsados. Os valores extraídos guardam o texto original da linha (para nomes com acentos).

### 3. Documento de identificação (`IdDocumentParser`)

**Primeiro tenta a zona de leitura óptica (MRZ, ICAO 9303)** com `MrzParser`:
- Linhas candidatas: só `[A-Z0-9<]`, depois de trocar `«` e espaços por `<`.
- Formatos: TD1 (3 linhas de 30), TD2 (2 de 36), TD3 (2 de 44).
- Dígitos de controlo ICAO: pesos `7, 3, 1` repetidos; `0–9` valem o próprio número, `A–Z` valem 10–35, `<` vale 0; soma módulo 10. Valida o do número do documento, o da data de nascimento, o da validade e o composto. Algum errado → MRZ rejeitada (passa às etiquetas).
- Extrai: `documentCode` (1.º carácter `P` → `PASSPORT`; `I`, `A`, `C` → BI ou DIRE, decidido pelo `documentType` da etiqueta, secção seguinte, ou deixado vazio), `documentNumber` (sem `<`), `birthDate` (`AAMMDD`; século: se `AA` > dois últimos dígitos do ano actual → 19AA, senão 20AA), `surname` e `givenNames` (`<` → espaço). `fullName = givenNames + " " + surname`, com a primeira letra de cada palavra em maiúscula.

**Sem MRZ válida, usa etiquetas** (`assets/ocr/id_document_labels.json`, **provisório** até haver exemplos reais — ver "Questões"):

```json
{
  "fullName":     ["NOME", "NOME COMPLETO", "NAME"],
  "birthDate":    ["DATA DE NASCIMENTO", "DATA NASC", "DATE OF BIRTH"],
  "documentNumber": ["N.º", "NO.", "NUMERO", "BI N"],
  "documentType": { "BI": ["BILHETE DE IDENTIDADE"], "PASSPORT": ["PASSAPORTE", "PASSPORT"], "DIRE": ["DIRE", "RESIDENCIA"] }
}
```

- Valor da etiqueta: o resto da linha depois da etiqueta (retirando `:` e espaços); se vazio, a linha seguinte.
- `birthDate`: `dd/MM/yyyy`, `dd-MM-yyyy` ou `dd.MM.yyyy`, data válida, idade 0–120.
- `documentNumber`: maiúsculas, sem espaços, `^[A-Z0-9]{5,20}$` (a mesma regra do S1-06).
- `fullName`: pelo menos duas palavras, só letras, espaços, `'` e `-` (regra do S1-06).
- Um valor que não cumpra a regra do campo não é proposto.

### 4. Livrete (`LivreteParser`)

Etiquetas em `assets/ocr/livrete_labels.json` (**provisório**, mesma questão):

```json
{
  "plate":   ["MATRICULA"],
  "make":    ["MARCA"],
  "model":   ["MODELO"],
  "year":    ["ANO DE FABRICO", "ANO"],
  "chassis": ["N.º DE QUADRO", "QUADRO", "CHASSIS"]
}
```

- `plate`: a primeira sequência, em qualquer linha (com ou sem etiqueta), que normalizada (sem espaços nem hífens) corresponde a um formato de matrícula activo; mostrada formatada pelo `displayTemplate`.
- `chassis`: primeiro um VIN de 17 caracteres `^[A-HJ-NPR-Z0-9]{17}$` (sem `I`, `O`, `Q`) depois da etiqueta ou, se não houver, em todo o texto; senão o valor da etiqueta, se cumprir a regra do S2-03 `^[A-Z0-9]{5,30}$` (veículos antigos).
- `year`: 4 dígitos entre 1900 e o ano actual + 1 (regra do S2-03).
- `make`, `model`: texto da etiqueta, 1–40 caracteres.
- Campo que o formulário do S2-07 não tenha → ignorado.

### 5. Folha de revisão (`OcrReviewSheet`) — "o utilizador confirma sempre"

- `showModalBottomSheet` com título `ocrReviewTitle` ("Confirme os dados lidos") e texto `ocrReviewHint` ("Lemos estes dados da fotografia. Corrija o que estiver errado antes de usar.").
- Uma linha por campo lido: etiqueta, `TextFormField` editável com o valor e as mesmas validações do formulário de destino, e uma caixa "Usar" (marcada por defeito).
- Se o formulário já tiver um valor diferente nesse campo: mostra `ocrReviewCurrent` ("No formulário: {valor}") por baixo, e a caixa "Usar" vem **desmarcada**. Nunca se substitui um valor existente sem o cliente marcar.
- Botões: primário azul `ocrUseData` ("Usar estes dados") e de contorno `ocrFillManually` ("Preencher à mão"). Nenhum botão laranja.
- Nenhum campo lido → não abre a folha; `SnackBar` `ocrNothingFound` ("Não conseguimos ler os dados. Preencha à mão.").
- "Usar estes dados" só copia os valores marcados para o formulário. **Não grava nada**: o cliente continua a ter de carregar no botão de gravar do formulário.
- No formulário, cada campo preenchido pelo OCR mostra `OcrPrefilledIndicator` (ícone `auto_awesome`, texto de ajuda `ocrPrefilled` "Preenchido a partir da fotografia — confirme") até o cliente o editar.
- Se algum campo do formulário estiver marcado como preenchido pelo OCR, o botão de gravar exige a caixa `ocrConfirmCheckbox` ("Confirmo que verifiquei os dados") marcada; sem ela fica desactivado.
- Acessibilidade: a folha tem `Semantics` com rótulos; o indicador tem `semanticLabel` igual ao texto de ajuda.

### 6. Onde se usa

| Ecrã | Quando | Destino dos valores |
| --- | --- | --- |
| Veículo (S2-07) | depois de tirar a fotografia do livrete | campos do formulário de veículo |
| KYC — frente do documento (S4-09) | depois de tirar a fotografia | se o perfil tiver em falta algum de nome, data de nascimento, tipo ou número de documento: botão `ocrCompleteProfile` ("Completar o perfil com estes dados") abre a folha; "Usar estes dados" abre o ecrã de perfil (S1-09) com os valores no formulário, e o cliente grava aí (`updateMyProfile`) |

O tipo de documento lido só é proposto se for `BI`, `PASSPORT` ou `DIRE`.

Fix anything that is wrong before using them.", "In the form: {value}", "Use", "Use these details", "Fill in manually", "We couldn't read the details.
