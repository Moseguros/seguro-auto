## Objectivo

Um único comando diz se a máquina tem tudo o que é preciso para correr o projecto, explica como instalar o que falta e descarrega as imagens Docker.

## Ficheiros

- `scripts/doctor.sh` — a verificação (bash; Linux, macOS, Git Bash no Windows; compatível com o bash 3.2 do macOS)
- `scripts/doctor.ps1` — atalho para o PowerShell que corre o `doctor.sh` no Git Bash
- `scripts/images.txt` — lista das imagens Docker do projecto
- `.claude/commands/verificar-ambiente.md` — comando `/verificar-ambiente` do Claude Code
- `.gitattributes` — fins de linha LF (o `mvnw` e os scripts falham nos contentores com CRLF)

## Especificação

O script verifica:

- **Git** e fins de linha LF;
- **Docker**: motor a correr, `docker compose` v2, contentores Linux, memória ≥ 4 GB;
- **imagens** de `scripts/images.txt` (`--fix` descarrega as que faltam, com o espelho `mirror.gcr.io` em caso de limite do Docker Hub);
- **JDK 17**: o do `JAVA_HOME`, que é o que o `./mvnw` usa;
- **Node** e **pnpm**;
- **Flutter** e **Android SDK** com emulador;
- **portas** 5432, 8080, 3000, 5173, 1025, 8025 e 8090;
- com `--full`, os testes do backend (`./mvnw -B verify`).

Comportamento:

- Uma ferramenta de uma pasta que ainda não existe (`web/`, `mobile/`, `infra/`) é aviso, não falta.
- O script sai com 1 se faltar algo obrigatório.

## Manutenção

- Quem acrescentar uma imagem ou mudar uma versão (Dockerfile, compose, Testcontainers) actualiza `scripts/images.txt`.
- Quem mudar uma versão exigida (Java, Node, pnpm, Flutter) actualiza as variáveis no topo do `doctor.sh`. O Node lê `web/.nvmrc` e o Flutter lê `mobile/pubspec.yaml`, se existirem.
